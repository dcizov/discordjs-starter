## Observed offerings, not a popularity leaderboard

Official public documentation inspected:

- [Dyno module catalog](https://docs.dyno.gg/en/modules): moderation, automod, reaction roles/onboarding, timed messages, reminders, tickets, feeds, levels and starboards.
- [Dyno Auto Message](https://docs.dyno.gg/en/modules/automessage): one-time/repeating channel messages, editable schedules, explicit delivery drift limitations. Dyno uses webhooks; that is **not** a permission requirement for Orbit's bot-authored messages.
- [MEE6 Polls](https://wiki.mee6.xyz/en/plugins/polls): poll creation/end commands, dashboard configuration and voting workflows. Its custom 20-option limit is **not** Discord's native poll API limit.
- [MEE6 plans](https://help.mee6.xyz/en/articles/710936-mee6-free-vs-premium-plans-comparison): documents timers, polls, welcome, ticketing, roles, levels, feeds and temporary channels. This is offering evidence, not an endorsement or purchase requirement.
- [Carl-bot documentation](https://docs.carl.gg/#/): explicitly lists suggestions, welcome messages, reaction roles, moderation, automod and custom commands.
- [sesh manual](https://sesh.fyi/manual/): dedicated event coordination, polls, reminders, timezone handling and dashboard workflows.

Several independent offerings establish recurring product categories. No representative adoption survey or feature-level usage telemetry was found/used; “most popular” and vendor user-count claims are deliberately not inferred. **Usefulness, scope and priorities below are Orbit-specific engineering/product judgments.** No vendor code, assets or proprietary UI was reused, and no paid service is introduced.

## Official compatibility references read before implementation

- [Discord.js 14.27.0](https://discord.js.org/docs/packages/discord.js/14.27.0), [interaction API](https://discord.js.org/docs/packages/discord.js/14.27.0/ChatInputCommandInteraction:Class), [PollData](https://discord.js.org/docs/packages/discord.js/14.27.0/PollData:Interface), [Poll](https://discord.js.org/docs/packages/discord.js/14.27.0/Poll:Class), [MessageCreateOptions](https://discord.js.org/docs/packages/discord.js/14.27.0/MessageCreateOptions:Interface).
- [Legacy guide command handling](https://discordjs.guide/legacy/app-creation/handling-commands) and [display component restrictions](https://discordjs.guide/legacy/popular-topics/display-components). Preserve the existing shared command definitions/registry and ephemeral deferral; do not copy the guide's raw interaction logging. Native polls cannot be combined with Components V2 messages.
- [Discord poll specification](https://docs.discord.com/developers/resources/poll): question ≤300 characters, answers ≤55, at most 10 answers, duration expressed in hours; native messages cannot be edited after creation. Missing results mean **unknown**, not zero. Counts may be approximate until finalized. Orbit deliberately caps duration at seven days rather than the API's 32-day maximum. Do not fetch voter identities.
- Discord.js [FetchGuildOptions](https://discord.js.org/docs/packages/discord.js/14.27.0/FetchGuildOptions:Interface) plus installed GuildManager/BaseGuild source: a bare guild ID may hit cache. Force current ownership metadata as well as fresh roles/members before trusting manager permissions; no approximate member/presence counts are needed in native execution.
- Installed @discordjs/rest 2.6.3 [RESTOptions](https://discord.js.org/docs/packages/rest/2.6.3/RESTOptions:Interface) and [RequestData](https://discord.js.org/docs/packages/rest/2.6.3/RequestData:Interface): `retries` covers 5xx/timeouts, not SDK 429 requeueing. Community transport explicitly sets `rejectOnRateLimit` and uses the documented AbortSignal; rate-limit refusals are known failures rather than ambiguous sends.
- Next App Router [Route Handlers](https://nextjs.org/docs/app/api-reference/file-conventions/route), [authentication/authorization](https://nextjs.org/docs/app/guides/authentication), [Server/Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components). Installed Next 16.4.3 is a 16.x App Router release; use the existing asynchronous params/cookies, force-dynamic/private no-store boundary and server-authorized DAL. Do not introduce newer-only caching directives, Cache Components, a second auth library or shared private-data caches.

The requested Discord.js version already matches the lockfile. No upgrade is required. Its versioned overview currently displays a Node 24.17+ installation sentence, but the **installed 14.27.0 package manifest** requires Node >=18; installed Next requires >=20.9 and this project deliberately requires >=22.14. The installed manifests and version-matched API/source are used for runtime compatibility; the overview's apparent current-README drift does not justify silently changing the deployment's Node major. Node 22.22.3 is tested here. Legacy/vendor examples never override the selected API contract.
